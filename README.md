# MetroSched – Intelligent Metro Train Induction Scheduling

MetroSched simulates a metro depot and line (SimPy) and schedules **train inductions**:
which train leaves the depot, when, and through which mainline entry point. Three
schedulers are compared on identical, unseen operating days:

| Scheduler | What it does |
|---|---|
| **FCFS baseline** | earliest-ready train, earliest free slot, reacts to current demand only |
| **Rule-based heuristic** | looks 12 min ahead, avoids bunching, prefers healthy trains, picks the entry that clears first |
| **PPO agent** | Gymnasium environment + Stable-Baselines3 (masked) PPO, warm-started by behaviour cloning |

On top of the schedulers sits an **agentic AI assistant**: a Claude LLM agent that takes the operator's
question in plain language ("festival tomorrow, platform 2 closed 08:00–09:30, what should we do?"), plans
what to test, runs what-if simulations with the schedulers through tools, checks the results and writes a
recommendation backed by the simulated numbers. The PPO agent is one of its tools. See
[`docs/AGENTIC_AI.md`](docs/AGENTIC_AI.md).

Technical details and the measured results are in [`docs/TECHNICAL_REPORT.md`](docs/TECHNICAL_REPORT.md);
the simulation design is in [`docs/PHASE1_DESIGN.md`](docs/PHASE1_DESIGN.md).

## ⚠️ Synthetic data – not KMRL data

**All data in this repository is synthetic.** It is generated by a configurable simulation
with random seeds. It is **not** actual Kochi Metro Rail Limited (KMRL) operational data, it
was not derived from KMRL data, and no part of this project has been validated against or
deployed in KMRL operations. Infrastructure and demand parameters in `data/config/` are
illustrative values for a single-line urban metro.

## Installation (Windows, local, no cloud services)

```powershell
cd metrosched
py -3.11 -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

Linux/macOS: `python3.11 -m venv .venv && source .venv/bin/activate && pip install -r requirements.txt`.
CPU-only PyTorch is enough (`pip install torch --index-url https://download.pytorch.org/whl/cpu`
installs a smaller build if you prefer).

## Execution

| Step | Command | Output |
|---|---|---|
| Generate synthetic data | `python main.py generate-data --seed 42` | `data/generated/*.csv` (30 days) |
| Run the baseline scheduler | `python main.py run-baseline --episodes 10` | `results/baseline/` + printed table |
| Train the RL agent | `python main.py train` | `models/ppo_metrosched.zip`, `results/training/` |
| Evaluate all schedulers | `python main.py evaluate` | `results/evaluation/` (120 unseen episodes) |
| Generate comparison graphs | `python main.py plot` | `results/plots/*.png` |
| Launch the dashboard | `python main.py dashboard` (or `streamlit run dashboard/app.py`) | http://localhost:8501 |
| Ask the agentic AI assistant | `python main.py agent "question"` (needs `ANTHROPIC_API_KEY`) | recommendation + tool trace |
| … without an API key | `python main.py agent --offline "question"` | same tools, rule-based planner |
| Everything in order | `python main.py all` | all of the above |
| Run the tests | `pytest` | unit + integration + dashboard tests |

Training takes ~30 min on a 2-core CPU with the default 400 000 steps
(`python main.py train --timesteps 100000` for a quicker run). A trained model is included in
`models/`, so evaluation, plots and the dashboard work without retraining.

## Dashboard pages

1. **Operations overview** – fleet KPIs, scenario and demand for any generated day; regenerate the dataset.
2. **Metro simulation** – choose scenario, seed, fleet size, exit tracks, headway, demand; start / reset; animated
   train movements, service vs requirement, Gantt, track occupancy, induction decisions.
3. **AI scheduling agent** – run FCFS / heuristic / PPO, recommended induction sequence with times, per-decision
   explanation (policy probabilities and train features), enforced constraints, comparison with FCFS on the same day.
4. **Performance analytics** – saved or live evaluation, improvement percentages, interactive charts, scenario
   breakdown, CSV export.
5. **System configuration** – fleet, track capacity, headways, maintenance probabilities, demand; validate, apply,
   save to `data/config/user_config.yaml`.
6. **Agentic AI assistant** – chat with the LLM agent (or the offline planner); live view of each tool call
   and the full reason → act → observe trace.

## Safety guarantee

Minimum headway, single occupancy of every track block and platform, closures, train
readiness and induction capacity are **hard constraints enforced by the simulation**: an
unsafe request is rejected or made to wait; it is never just penalised. This holds for every
scheduler including PPO. Every evaluated day is independently re-audited from its occupancy
logs; the audit reports zero violations for all schedulers.
